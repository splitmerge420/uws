# INV-004: Data Classification

| Field | Value |
|---|---|
| **ID** | INV-004 |
| **Severity** | mandatory |
| **Status** | active |
| **Registry key** | `INV-4` in `toolchain/invariants_registry.py` |

## Statement

All data must be classified by sensitivity before processing or storage.

## Rationale

Without a known sensitivity label, a system cannot make correct decisions about
encryption strength, retention, sharing, or deletion.  Classification is a prerequisite
for every downstream data-handling control.

## Data Classes

| Class | Description | Examples |
|---|---|---|
| **CLASS_A** | Highest sensitivity — health, financial, legal, biometric | Medical records, payment details, credentials |
| **CLASS_B** | Standard business data | Email, calendar, documents |
| **CLASS_C** | Public / non-sensitive | Published blog posts, public API responses |

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/constitutional_engine.rs` | `StateSnapshot::data_class` | Runtime classification field |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-4"]` | Canonical registry entry |
| `toolchain/zero_trust_gate.py` | `validate_manifest()` | Enforces `data_handling_class` field in integration manifests |
| `integrations/*.yaml` | `data_handling_class` | Declared per integration |

## Guard Patterns

Compliant code must reference: `data_class`, `data_classification`, `CLASS_A`, `CLASS_B`, `CLASS_C`, `sensitivity`

## Test Vectors

| Scenario | Expected |
|---|---|
| Integration manifest missing `data_handling_class` | gate rejects with `MISSING_DATA_CLASS` |
| `data_handling_class: CLASS_A` data routed through unencrypted channel | INV-011/012 violation |
| All three classes present in registry | gate passes |
