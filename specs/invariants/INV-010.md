# INV-010: Interoperability

| Field | Value |
|---|---|
| **ID** | INV-010 |
| **Severity** | mandatory |
| **Status** | active |
| **Registry key** | `INV-10` in `toolchain/invariants_registry.py` |

## Statement

All data formats must be standards-compliant (JSON-LD, FHIR, W3C PROV, iCalendar, vCard, etc.).

## Rationale

Proprietary formats create walled gardens.  Standards-compliant formats allow data to
move freely between systems, fulfil INV-018 (Data Portability), and prevent vendor
lock-in at the data layer.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/formatter.rs` | `OutputFormat` | Supports JSON, YAML, CSV, table — all open formats |
| `src/executor.rs` | Response handling | Raw API JSON preserved as-is |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-10"]` | Canonical registry entry |

## Required Standards by Domain

| Domain | Standard |
|---|---|
| General data | JSON (RFC 8259), YAML 1.2 |
| Linked data | JSON-LD (W3C) |
| Health | FHIR R4 (HL7) |
| Provenance | W3C PROV-DM |
| Calendar | iCalendar (RFC 5545) |
| Contacts | vCard (RFC 6350) |
| Cryptographic provenance | JWT (RFC 7519) |

## Test Vectors

| Scenario | Expected |
|---|---|
| Calendar export is valid iCalendar RFC 5545 | pass |
| Contact export is valid vCard RFC 6350 | pass |
| API response wrapped in proprietary binary format with no export path | violation |
