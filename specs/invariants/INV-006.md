# INV-006: Provider Abstraction

| Field | Value |
|---|---|
| **ID** | INV-006 |
| **Severity** | mandatory |
| **Status** | active |
| **Registry key** | `INV-6` in `toolchain/invariants_registry.py` |

## Statement

All cloud/AI provider calls must go through an abstraction layer.

## Rationale

Calling a cloud or AI provider directly makes the code brittle: any provider outage,
deprecation, or price change requires invasive surgery.  An abstraction layer gives the
system a single seam at which fallback routing (INV-007), audit logging (INV-003), and
vendor-balance enforcement can be applied uniformly.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/ms_graph.rs` | `MsGraphClient` | Provider-specific driver behind the abstraction |
| `src/apple.rs` | `AppleClient` | Provider-specific driver |
| `src/services.rs` | `SERVICES` table | Service registry (alias → api_name) |
| `src/main.rs` | `resolve_ms_service`, `resolve_apple_service` | Dispatch layer |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-6"]` | Canonical registry entry |

## Dangerous Patterns

```python
from openai import OpenAI          # ← direct import, VIOLATION
from anthropic import Anthropic    # ← direct import, VIOLATION
from google import genai           # ← direct import, VIOLATION
```

## Guard Patterns

Compliant code must reference at least one of:
`provider`, `multi_provider`, `fallback`, `ProviderRouter`, `MultiProviderLLM`, `vendor_balance`

## Test Vectors

| Scenario | Expected |
|---|---|
| Direct `import openai` without surrounding provider abstraction | violation |
| All provider calls routed through `ProviderRouter` | pass |
