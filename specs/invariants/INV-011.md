# INV-011: Encryption at Rest

| Field | Value |
|---|---|
| **ID** | INV-011 |
| **Severity** | critical |
| **Status** | active |
| **Registry key** | `INV-11` in `toolchain/invariants_registry.py` |

## Statement

All sensitive data must be encrypted at rest using AES-256-GCM or a quantum-resistant
algorithm (e.g., ML-KEM-768).

## Rationale

Data at rest is vulnerable to physical theft, storage-layer breaches, and backup
exfiltration.  AES-256-GCM provides authenticated encryption with associated data
(AEAD), making tampering detectable.  The quantum-resistant upgrade path (INV-013) must
be possible without breaking this invariant.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/credential_store.rs` | `CredentialStore` | AES-256-GCM encryption of all stored credentials |
| `src/token_storage.rs` | `TokenStorage` | Encrypted OAuth token persistence |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-11"]` | Canonical registry entry with forbidden patterns |

## Forbidden Patterns

The following patterns indicate plaintext credential storage and are auto-detected by
the linter:

```python
password = "s3cr3t"     # ← VIOLATION
api_key  = "sk-..."     # ← VIOLATION
secret   = "abc123"     # ← VIOLATION
token    = "ghp_..."    # ← VIOLATION
```

## Test Vectors

| Scenario | Expected |
|---|---|
| `password = "literal"` in source file | linter flags VIOLATION |
| Credential stored via `CredentialStore::store()` | encrypted on disk, passes |
| Decrypted credential not re-encrypted before write | advisory violation |
