# INV-024: Graceful Degradation

| Field | Value |
|---|---|
| **ID** | INV-024 |
| **Severity** | mandatory |
| **Status** | active |
| **Registry key** | `INV-24` in `toolchain/invariants_registry.py` |

## Statement

Systems must degrade gracefully under failure rather than crashing entirely.

## Rationale

Production systems encounter failures: network timeouts, provider outages, malformed
responses, disk full.  A system that crashes on any unexpected input is untrustworthy.
Graceful degradation means: detect the failure, emit a structured error (INV-021),
fall back to a safe state (INV-035), log the event (INV-003), and continue serving
other requests where possible.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/error.rs` | `GwsError` | Structured error type; never panics at top level |
| `src/main.rs` | `run()` → `print_error_json()` | Structured JSON error on failure |
| `src/discovery.rs` | Cache fallback | Uses cached doc when network fails |
| `toolchain/spheres_pipeline.py` | Stage orchestrator | Fail-fast with exit codes; no silent swallow |
| `toolchain/stress_test.py` | Resilience scoring | Measures graceful degradation under load |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-24"]` | Canonical registry entry |

## Degradation Levels

| Level | Behaviour |
|---|---|
| **L0** (normal) | Full functionality |
| **L1** (network degraded) | Use cached data; warn user |
| **L2** (provider down) | Fall back to alternative provider (INV-007) |
| **L3** (critical failure) | Emit structured error; preserve audit log; exit cleanly |
