# INV-022: Type Safety

| Field | Value |
|---|---|
| **ID** | INV-022 |
| **Severity** | warning |
| **Status** | active |
| **Registry key** | `INV-22` in `toolchain/invariants_registry.py` |

## Statement

All public interfaces must have type annotations.

## Rationale

Type annotations are machine-checked documentation.  They prevent entire classes of
runtime errors (wrong argument type, missing field), improve IDE tooling, and make
refactoring safer.  In Python, PEP 484 type hints enable mypy static checking.  In
Rust, the type system enforces this at compile time.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/` (all `.rs` files) | Rust type system | Enforced at compile time by Rust |
| `toolchain/*.py` | mypy-compatible type hints | Advisory; `from typing import Dict, Any, List` used throughout |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-22"]` | Canonical registry entry |

## Applied Rules

| Language | Requirement |
|---|---|
| Rust | Compiler-enforced; no annotation needed |
| Python | All public function signatures must have `def f(x: Type) -> ReturnType:` annotations |
| TypeScript | Strict mode (`"strict": true` in tsconfig) |

## Test Vectors

| Scenario | Expected |
|---|---|
| Python public function with no type hints | warning violation |

| Rust function — no annotation needed | pass (compiler enforces) |
