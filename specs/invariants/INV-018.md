# INV-018: Data Portability

| Field | Value |
|---|---|
| **ID** | INV-018 |
| **Severity** | mandatory |
| **Status** | active |
| **Registry key** | `INV-18` in `toolchain/invariants_registry.py` |

## Statement

Users must be able to export all their data in standard, machine-readable formats.

## Rationale

Data portability (GDPR Art. 20) prevents platform lock-in at the data layer.  Users
who can export their data can migrate to competitors, run local backups, and maintain
true ownership.  It also fulfils INV-010 (Interoperability) in practice.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/formatter.rs` | `OutputFormat::{Json,Yaml,Csv}` | All API responses exportable in open formats |
| `src/executor.rs` | `--output <path>` flag | Binary/file downloads to local paths |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-18"]` | Canonical registry entry |

## Supported Export Formats

| Format | Use case |
|---|---|
| JSON | Machine-readable structured data |
| YAML | Human-readable configuration |
| CSV | Tabular data for spreadsheet tools |
| iCalendar | Calendar data (RFC 5545) |
| vCard | Contact data (RFC 6350) |
