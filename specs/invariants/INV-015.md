# INV-015: Key Rotation

| Field | Value |
|---|---|
| **ID** | INV-015 |
| **Severity** | mandatory |
| **Status** | active |
| **Registry key** | `INV-15` in `toolchain/invariants_registry.py` |

## Statement

All cryptographic keys must have explicit rotation schedules and support automated
rotation.

## Rationale

A key that never rotates is a single point of compromise.  If a long-lived key is
exfiltrated, all data encrypted with it is permanently exposed.  Rotation limits the
blast radius of any key compromise to the rotation interval.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/credential_store.rs` | `CredentialStore` | Stores keys; rotation interface must be added |
| `src/auth.rs` | `refresh_token()` | OAuth token refresh — a form of key rotation |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-15"]` | Canonical registry entry |

## Rotation Schedule Requirements

| Key Type | Maximum Rotation Interval |
|---|---|
| OAuth access token | As per provider (typically 1 hour) |
| OAuth refresh token | 90 days |
| AES-256-GCM data encryption key | 365 days |
| PQC signing key | 180 days |

## Test Vectors

| Scenario | Expected |
|---|---|
| Key created with no `expires_at` or rotation schedule | advisory violation |
| `refresh_token()` called on expiry | pass |
| Key older than max interval still in use | mandatory violation |
