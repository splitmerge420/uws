# INV-003: Audit Trail

| Field | Value |
|---|---|
| **ID** | INV-003 |
| **Severity** | critical |
| **Status** | active |
| **Registry key** | `INV-3` in `toolchain/invariants_registry.py` |

## Statement

Every governance decision, data access, and state change must be logged immutably.

## Rationale

Without an audit trail, accountability is impossible.  An immutable log allows post-hoc
forensics, rollback planning, and trust verification.  The log itself must be append-only
and cryptographically chained (SHA3-256) so that tampering is detectable.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/audit_chain.rs` | `AuditChain::append()` | Append-only, SHA3-256 chained log |
| `src/council_github_client.rs` | `ProvenanceTrailer` | Per-operation audit record attached to every result |
| `toolchain/acp_governance.py` | `verify_chain()` / `verify_integrity()` | Offline chain verification |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-3"]` | Canonical registry entry |

## Dangerous Patterns

```rust
fn delete_record(id: &str) {
    db.remove(id);   // ← VIOLATION: no audit log entry
}
```

```python
def destroy(path):
    shutil.rmtree(path)   # ← VIOLATION
```

## Guard Patterns

Compliant code must contain at least one of:
`audit`, `log`, `logger`, `logging`, `record`, `trace`, `AuditTrail`, `AuditChain`

## Test Vectors

| Scenario | Expected |
|---|---|

| `delete` function with `audit_chain.append(...)` nearby | pass |
| `AuditChain` with tampered hash | `verify_chain()` returns `False` |
