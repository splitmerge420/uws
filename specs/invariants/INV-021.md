# INV-021: Error Boundaries

| Field | Value |
|---|---|
| **ID** | INV-021 |
| **Severity** | mandatory |
| **Status** | active |
| **Registry key** | `INV-21` in `toolchain/invariants_registry.py` |

## Statement

Every module must have error boundaries that prevent cascade failures.

## Rationale

An unhandled exception in one module should never take down the entire system.  Error
boundaries act as circuit breakers: they catch exceptions, log them (INV-003), and
return a structured error rather than propagating a panic or unhandled traceback.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/error.rs` | `GwsError` | Typed error enum; all errors flow through this type |
| `src/main.rs` | `run()` → `print_error_json()` | Top-level boundary: all errors serialised to JSON |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-21"]` | Canonical registry entry |
| `toolchain/spheres_pipeline.py` | Pipeline orchestrator | Fail-fast with structured error propagation |

## Dangerous Patterns

```python
try:
    do_something()
except:          # ← bare except — swallows all errors, VIOLATION
    pass
```

## Guard Patterns

Compliant code must use typed exception handling:

```python
except ValueError as e:     # ✅ typed exception
except (IOError, OSError):  # ✅ tuple of typed exceptions
```

## Test Vectors

| Scenario | Expected |
|---|---|
| `except:` with empty body in Python file | linter flags VIOLATION |
| `except Exception as e: log(e); raise` | pass |
| Rust `unwrap()` in production path (not test) | advisory violation |
