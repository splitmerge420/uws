# INV-009: Offline Capability

| Field | Value |
|---|---|
| **ID** | INV-009 |
| **Severity** | mandatory |
| **Status** | active |
| **Registry key** | `INV-9` in `toolchain/invariants_registry.py` |

## Statement

Critical operations must function without network connectivity.

## Rationale

Network access is a privilege, not a guarantee.  A system that fails catastrophically
when offline is untrustworthy.  Critical operations — authentication verification,
local audit log reads, schema introspection against a cached Discovery Document —
must degrade gracefully to a local-first mode.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/discovery.rs` | Discovery Document cache | 24-hour on-disk cache prevents repeated network calls |
| `src/auth.rs` | Token storage | Access tokens cached locally |
| `src/token_storage.rs` | `TokenStorage` | Encrypted token persistence |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-9"]` | Canonical registry entry |

## Guard Patterns

Compliant code must handle `ConnectionRefused`, `NetworkError`, or equivalent and fall
back to a cached or local mode rather than panicking.

## Test Vectors

| Scenario | Expected |
|---|---|
| Discovery Document fetch fails; cache exists | uses cached doc, continues |
| Discovery Document fetch fails; no cache | returns structured error, not panic |
| Token refresh fails when offline | uses cached token until expiry |
