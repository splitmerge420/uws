# INV-007: Vendor Balance

| Field | Value |
|---|---|
| **ID** | INV-007 |
| **Severity** | critical |
| **Status** | active |
| **Registry key** | `INV-7` in `toolchain/invariants_registry.py` |

## Statement

No single-vendor dependency. Every external API call must have a fallback provider.
No single provider may hold more than 47 % of the system's critical-path requests.

## Rationale

Vendor lock-in is an existential risk.  If a single provider becomes unavailable,
triples its price, or changes its terms, a system with no fallback collapses.  The 47 %
dominance cap prevents any provider from becoming structurally indispensable.

## Implementation

| File | Symbol | Role |
|---|---|---|
| `src/council_github_client.rs` | `check_vendor_balance()` | Runtime dominance-cap enforcement |
| `src/constitutional_engine.rs` | `ConstitutionalEngine::enforce()` | Included in full enforcement sweep |
| `toolchain/invariants_registry.py` | `INVARIANTS["INV-7"]` | Canonical registry entry |
| `integrations/*.yaml` | `fallback_providers` | Declared per integration |

## Dangerous Patterns

```python
openai.chat.complete(...)      # ← no fallback declared, VIOLATION
anthropic.messages.create(...) # ← no fallback declared, VIOLATION
```

## Guard Patterns

Compliant code must reference at least one of:
`fallback`, `alternative`, `vendor_balance`, `multi_provider`, `PROVIDERS =`, `provider_chain`

## Test Vectors

| Scenario | Expected |
|---|---|
| Single provider, no `fallback_providers` declared | violation |
| `fallback_providers: [openai, anthropic]` | pass |
| Single provider at > 47 % of call volume | dominance cap triggered |
