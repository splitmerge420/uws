## 1. Purpose

This protocol extends INV-17 to cover developer behavioral traces — one of the highest-value emerging data categories in AI training. It establishes provenance tracking, tiered valuation, and direct compensation for contributors whose cognitive work generates outsized model improvement.

## 2. Core Principle

Developers who generate high-signal training data should capture a meaningful share of the value they create.

This is not redistribution. It is incentive-aligned economics. Properly compensated contributors produce higher-quality data, accelerating capability development for all participants.

## 3. Data Category Definition

Developer Trace Data includes, but is not limited to:

- coding patterns and architectural decisions;
- debugging strategies and refactoring sequences;
- edge-case handling and error recovery behaviors;
- code review interaction patterns;
- IDE usage telemetry, with explicit consent.

Data sources should be symmetric, with no single platform preferred:

- Cursor;
- VS Code;
- JetBrains;
- Windsurf;
- Zed;
- Vim / Neovim;
- Xcode;
- Android Studio;
- GitHub / GitLab / Bitbucket commit histories, with consent;
- CI/CD behavioral data;
- any IDE implementing the INV-17 consent protocol.

## 4. Tiered Valuation & Compensation

| Tier | Criteria | Compensation | Attribution Method |
|---|---|---|---|
| Tier 1 — Standard | All consented contributors | >=15% floor of gross value | Baseline participation |
| Tier 2 — High-Impact | Traces demonstrably improving specific benchmarks | Enhanced dividend, market-discovered | Influence functions / Data Shapley |
| Tier 3 — Last Starfighter | Contributions creating outsized capability jumps | Exceptional dividend, power-law | Verifiable attribution / INV-13 cross-sphere review |

## 5. Constitutional Constraints

- No Exclusive Access: all model families may purchase developer traces under INV-7c model-family caps.
- Provenance Required: every trace should carry contributor identity or pseudonymous identity, IDE, timestamp, language, and framework tags.
- Granular Consent: developers consent per category, such as code patterns, debugging, architecture, review behavior, or telemetry.
- No Bundling: IDE subscriptions must not be conditioned on trace marketplace participation.
- Marketplace Model: traces flow through a neutral INV-17 marketplace, not closed ecosystem loops.

## 6. Economic Thesis

Compensating high-value contributors increases total system value:

- better incentives produce higher quality and volume of traces;
- higher quality data accelerates model improvement;
- faster improvement increases willingness to pay for resulting tools;
- multiple competing buyers create price discovery and higher total compensation for developers.

This is the INV-17 efficiency argument applied to developer cognition.
